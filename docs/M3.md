# M3: recipe book and cooking preview

Open **Recipe book** from Ingredients. Create a recipe with a name, positive base
servings, comma-separated tags, instructions and notes. Add phases and move them
up/down to set their order. Each phase supports required or optional ingredient
lines and alternative groups. Filter the food picker by name, choose a food,
and enter a positive quantity and explicit unit. Archived ingredients remain
available so existing recipes keep working. Alternative groups require at least
two distinct ingredients; options cannot themselves be optional. The group can
be optional. Invalid structures cannot be saved; the screen shows the validation
message and retains the draft for correction.

Save opens recipe details. Cooking preview defaults to base servings, excludes
optional entries and chooses the first option in each required group. Change
servings, include optional entries/groups, and select alternatives to immediately
recalculate scaled lines in phase order and whole/per-serving totals. Unknown
values and unsupported conversions show incomplete totals, known subtotals and
ingredient/line-specific reasons. No food density or piece weight is inferred.
Preview calls the M1 calculation engine directly.

Every editor text/choice/structure change writes the raw draft in a SQLite
transaction, including incomplete numeric input. Back keeps the draft, and the
ingredient screen and recipe book offer Resume unfinished recipe after restart.
Only one unfinished recipe is supported; resume and save it or explicitly discard
it before editing another. Discard requires confirmation. Saving atomically
updates the recipe and ingredient dependencies and clears the draft. A failed
save leaves both the saved recipe and draft intact. Pause also flushes the draft;
rotation/resume can keep widgets or rebuild from the stored draft. Preview choices
are temporary and do not modify a saved recipe.

Schema version 3 adds recipe JSON payloads, a foreign-key dependency table and a
single raw draft slot. Migration is in the same transaction as initialization and
catalog reconciliation. Ingredient archives do not delete dependencies. Raw
recipe JSON is an internal persistence contract, not the M6 portable backup.

## Verification

Run `python -m unittest discover -v`. With Kivy installed and a working SDL/OpenGL
window, run `python -m unittest tests.ui_smoke -v` (SDL's offscreen driver may be
used on a headless host). Tests cover recipe round trips, editing/ordering,
scaling, invalid/contradictory groups, dangling hidden references, draft recovery,
foreign keys, migration rollback and UI preview equality with domain results.

On the Galaxy S25, verify:

- Create a two-phase recipe, reorder phases, add required/optional lines and an
  optional alternative group. Save, reopen and edit all text fields.
- Scale two servings to three, switch alternatives, and include/exclude optional
  groups. Compare displayed quantities and totals with expected food values.
- Use an unknown nutrient and unsupported unit; verify explanations and no false
  complete total. Correct the food conversion and reopen preview.
- Enter invalid servings or remove alternatives down to one option: Save must
  stay in the editor with an explanation.
- Enter unfinished text, press Android Back, resume the draft; background/resume,
  rotate and kill/relaunch the process. Draft values must remain. Confirm discard
  explicitly and verify the saved recipe did not change.
- Check keyboard obstruction, long food names, font scaling, scrolling and food
  spinner selection. Install as an update with the existing signing key.

Actual Galaxy S25 behavior and APK packaging require device/build verification;
a desktop smoke run does not establish those results.

Implementation verification: 43 domain/storage/catalog tests and seven Kivy
smoke tests passed using Python 3.12 and Kivy 2.3.1 with SDL offscreen. No Android
APK build or physical-device verification was performed for this milestone.
