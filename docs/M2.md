# M2: ingredient catalog and persistence

The app now opens a browsable, searchable list of 26 USDA foods. Tap a food for
its nutrition reference, conversion assumptions, source and personal corrections.
Add custom ingredients, edit nutrition or reference units, add/remove conversion
mappings, archive/unarchive foods, or reset starter corrections with confirmation.
Blank nutrient fields mean unknown; zero is a known zero. Decimal commas work.
Nutrition entries always describe the displayed reference amount and unit.
When changing that reference, enter the corresponding nutrient values yourself.

## Build and launch

The package source is now the repository root so the APK includes `almanac/`
and `data/staples.json`. Keep using the Buildozer configuration in `setup/`:

```sh
# From the repository root, in your existing working Android build environment:
git pull
python -m unittest discover -v
python tools/build_staples.py
cd setup
buildozer android debug
buildozer android deploy run
```

Install the resulting APK as an update using the same signing key. Package
`org.almanac.almanac` and the `FoodLoggerApp` class are unchanged, preserving
Kivy's existing writable directory. App version is 0.2.0. Android tooling remains
as configured in the previously working spike; this milestone does not claim a
new APK build or actual Galaxy S25 verification.

For desktop testing with Kivy installed, run `python main.py` from the repository
root, or `cd setup` and `python main.py`. No network is required at runtime.

## Storage and catalog upgrades

`almanac.db` is created under Kivy's private persistent `user_data_dir`. The
bundled JSON is read-only. The old phone `foods.db`, if present, is imported once
inside the first database transaction and left untouched as a recovery copy.
Both earlier formats are supported: the original 12-food numeric-ID spike and
the sourced M1 database. Unchanged rounded 12-food fixture values become the
sourced values; changed nutrients/categories and unknown values are retained.
Renamed/unrecognized original foods become custom ingredients rather than
being guessed into starter matches. M1 stable IDs retain their edits/conversions.

Schema migrations are sequential through SQLite `user_version=2`. Foreign keys
are enabled on each connection. DDL, initialization, seed reconciliation and
legacy import share one `BEGIN IMMEDIATE` transaction; failures and process death
roll back the whole operation. The initialized marker is committed last. A
failed initialization is retried on the next launch, and a failed upgrade leaves
the earlier data intact. Unknown newer schemas are rejected without changes.
The app reports startup/write failures and permits retry; it never deletes a
user database to recover from an error.

`seed_records` stores canonical JSON baselines, SHA-256 hashes, catalog versions,
availability and pin flags. `ingredients` references its baseline by foreign key
or stores a custom definition. Each starter override is stored separately, per
field and per nutrient. A conversion map and its descriptions are a single
logical edit so a new description cannot silently label a corrected old weight.
Changing the reference amount/unit keeps all entered nutrients and conversions
together as overrides, so later baseline values cannot be mixed into that basis.
Custom ingredients get UUIDs. Baselines and catalog provenance are retained for
later backup work. No recipe/meal tables are created ahead of their milestones.

On each startup, the complete incoming catalog is validated before a write.
Unedited baseline fields update; corrected fields, custom records and archive
state remain. An override remains intentional even if a later baseline happens
to equal it. Resetting corrections explicitly removes those overrides. If a
catalog changes an edited ingredient's measurement basis, the earlier baseline
is pinned to avoid mixing values defined for different reference amounts/units.
The detail screen explains that pin; reset uses the stored baseline. A removed
seed retains its last definition and ID, with a visible earlier-catalog notice.
Catalog corrections with an invalid baseline/override combination are rejected
atomically rather than discarding corrections.

Archive is reversible and never deletes ingredient records or stable IDs. The
default list hides archived records; Include archived makes them accessible.
Repository `get` and domain conversion can still resolve archived records, which
will preserve references when recipes arrive in M3. Search is literal, Unicode
case-insensitive, and matches all words across name and category.

The current catalog is small, so search and initialization run on the UI thread.
Profile and move longer work off that thread when expanding the data volume.
Full backup/restore remains M6; the retained legacy database is not a replacement
for a user-facing backup facility.

## Automated verification

```sh
python -m unittest discover -v
# With Kivy 2.3.1 installed and an OpenGL window provider:
python -m unittest tests.ui_smoke -v
```

The second suite can use SDL's offscreen provider on Linux:
`SDL_VIDEODRIVER=offscreen KIVY_NO_ARGS=1 python -m unittest tests.ui_smoke -v`.
It exercises actual Kivy controls, save validation, archive/restoration, conversion
editing/removal, reset confirmation and unsaved-edit navigation. CI runs both
suites. The storage suite tests fresh installs, populated schema upgrades,
field-level override precedence, source integrity, original and M1 legacy imports,
transaction failures, and abrupt subprocess termination before commit. It also
checks foreign keys and old-data usability after a failed upgrade.

## Galaxy S25 test checklist

1. Install as an update, without uninstalling or clearing storage. Launch in
   airplane mode. Expect 26 USDA foods even if the previous spike showed 12.
2. Search for egg, open its detail, and confirm 143 kcal per 100 g and a large
   piece mapping of 50 g. Open a liquid and confirm no mass/volume guess is made.
3. Edit egg protein and its piece conversion to 53 g, save, close/force-stop the
   app, and reopen. Confirm both corrections remain and the source is visible.
4. Add a food with a custom name, reference of 1 piece, and a `g` conversion such
   as 0.02 (1 g = 0.02 piece for a 50 g piece). Leave one nutrient blank and set
   another to 0. Confirm Unknown and 0 remain distinct after reopening.
5. Try negative values, a blank name, an invalid conversion and duplicate units.
   Saving should explain the problem without leaving the editor or losing input.
6. Archive a food; confirm it disappears from the default list. Include archived,
   open it, unarchive, and confirm it returns. Reset a starter correction, first
   canceling and then confirming; its original values should return.
7. Edit a field, press Android Back, and try both keeping and discarding edits.
   Scroll the full form, use decimal input, and check that the keyboard does not
   cover the active field. Repeat with larger Android font/display settings.
8. Build/install the same version again without uninstalling. Confirm custom
   foods, corrections, unknowns, conversions and archive state are unchanged.

Desktop/offscreen checks cannot confirm Android keyboard, signing/update behavior
or lifecycle on the phone. Record those outcomes after testing. Do not clear app
data to make the new catalog appear; this milestone performs that upgrade.
